# 数据与业务契约

reviews 仅覆盖实际复核，缺失不是支持或否定。supported 指现有材料支持申报，不保证不存在其他异常。permissions 记录合法共用代办原因。presence 是本地合成签到，只用于审核分析，不包含真实个人信息。

## 数据集合

- `claims`：主键为 `claim`；必填字段 `claim, school, session, teacher, agent, venue, amount, attachments`，当前 36 条。
- `presence`：主键为 `record`；必填字段 `record, claim, person, minutes, source`，当前 378 条。
- `reviews`：主键为 `claim`；必填字段 `claim, reviewed_at, outcome, selection`，当前 12 条。
- `policies`：主键为 `policy`；必填字段 `policy, amount_threshold, daily_budget`，当前 1 条。
- `permissions`：主键为 `agent`；必填字段 `agent, reason, valid_from`，当前 1 条。

集合中的主键不得重复；schema 的 foreign 引用须指向已存在的记录。可空字段保留 null 的业务含义，不自动补零。

## 查询与材料

GET 查询使用 UTF-8 JSON，错误参数返回 400，不存在的接口返回 404。重复的单值参数视为无效。summary 与 HTTP 调用同一组只读计算，材料包含数据内容指纹和生成时间，便于核对输入。当前输出描述已有数据，不承诺未实现的推断结论。

## 现有办理协作

review_dispatch.assign 逐笔派工并避开学校利益关联，document_requests.request 仅向本校索取该笔记录，review_feedback.resolve 登记复核来源与未定结论；现行队列按金额，尚无关系组线索或组内部分完成传播。

每个操作在本地业务日志的事务中更新；失败不提交半条办理记录。已有人工流程可以继续使用，新增分析尚未作为这些操作的有效依据。接口传入业务标识，未知标识或不满足条件返回错误，不自动补建对象。
